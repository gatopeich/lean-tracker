═══════════════════════════════════════════════════════════════════
                              OVERVIEW
═══════════════════════════════════════════════════════════════════

Lean Tracker is a minimal Android application that tracks changes on 
website content with intelligent cookie management and visual content 
selection. The app accepts URLs shared from browsers, performs periodic 
polling, detects content changes, and notifies users with visual diffs.

                          KEY FEATURES
═══════════════════════════════════════════════════════════════════

✅ Content Tracking
   • Accept URLs via Android intents (browser sharing)
   • Periodic polling (configurable, default 24 hours)
   • Automatic change detection
   • Push notifications with visual diff
   • Auto-naming: [selector] - [page title]

✅ Element Selection
   • Visual point-and-click in WebView
   • JavaScript injection for element highlighting
   • CSS selector generation
   • XPath support (simple cases)
   • Optional regex filtering

✅ Security & Cookies
   • Encrypted credential storage
   • WebView for secure login
   • Smart cookie management:
     - Auth cookies: session, token, jwt → kept
     - Tracking cookies: _ga, utm_ → discarded
   • Automatic cookie consent rejection

✅ User Experience
   • Material Design 3 UI
   • Dark theme support
   • Clear visual diffs (green/red)
   • Smooth Compose animations
   • Network-aware scheduling

═══════════════════════════════════════════════════════════════════
                          BUILD INSTRUCTIONS
═══════════════════════════════════════════════════════════════════

PREREQUISITES:
  • Android Studio Hedgehog (2023.1.1) or newer
  • JDK 17 or newer
  • Android SDK API 34

STEPS:
  1. Clone repository:
     $ git clone https://github.com/gatopeich/lean-tracker.git
     $ cd lean-tracker

  2. Open in Android Studio:
     File → Open → Select project directory

  3. Sync Gradle dependencies:
     (Wait for automatic sync or click "Sync Now")

  4. Build debug APK:
     $ ./gradlew assembleDebug
     Output: app/build/outputs/apk/debug/app-debug.apk

  5. Build release APK:
     $ ./gradlew assembleRelease
     Output: app/build/outputs/apk/release/app-release.apk

  6. Install on device:
     $ ./gradlew installDebug

  7. Or run from Android Studio:
     Select device/emulator → Click Run ▶️

                          TESTING GUIDE
═══════════════════════════════════════════════════════════════════

1. URL SHARING TEST:
   • Open Chrome/Firefox on device
   • Navigate to any webpage
   • Tap Share → Lean Tracker
   • Verify URL pre-filled in Add/Edit screen
   • Verify page title auto-fetched

2. VISUAL SELECTION TEST:
   • Tap "Visual Select" button
   • Verify page loads in WebView
   • Tap on any element (e.g., heading)
   • Verify element highlights in purple
   • Verify selector shown at top
   • Tap ✓ to confirm
   • Verify selector copied to form

3. TRACKING TEST:
   • Complete adding a tracked item
   • Wait for background check (or trigger manually)
   • Change content on the tracked page
   • Verify notification appears
   • Tap notification
   • Verify diff display with colors

4. COOKIE TEST:
   • Track a page requiring login
   • Verify WebView opens for authentication
   • Log in
   • Verify subsequent checks don't require login
   • Check database for auth cookies only

═══════════════════════════════════════════════════════════════════
                          DESIGN DECISIONS
═══════════════════════════════════════════════════════════════════

1. MINIMAL DEPENDENCIES
   Only essential libraries included to keep APK small:
   - Jetpack Compose (modern UI)
   - Room (database)
   - WorkManager (background)
   - OkHttp (networking)
   - JSoup (HTML parsing)

2. NO AUTOMATED TESTS
   Per requirements to keep code minimal. Production apps
   should include comprehensive tests.

3. SIMPLE DIFF ALGORITHM
   Line-by-line comparison instead of sophisticated algorithms
   (Myers, patience diff) to reduce code size.

4. BASIC XPATH SUPPORT
   Simple conversion to CSS selectors instead of full XPath
   parser library (would add significant code).

5. WEBVIEW AUTHENTICATION
   Relies on WebView for login instead of custom UI, following
   requirements for minimal implementation.

6. INLINE COMMENTS
   Only added where complexity requires clarification, not for
   obvious code.
